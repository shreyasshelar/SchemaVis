The cold start problem

SchemaVis runs on GCP Cloud Run, which scales to zero when idle. After a period of inactivity the backend spins down. The first incoming request must wait ~5 s for a new container to start before getting a response. On the auth page this means a user clicks Create account, sees nothing happen for several seconds, and assumes the form is broken.

❌ Before fix

User opens /register
Fills 3 fields…
Clicks Create account0 ms
POST /api/auth/register0 ms
Container cold-starting…+4 800 ms
Backend responds~5 000 ms

✅ After fix

User opens /register0 ms
GET /api/auth/me (warm-up)0 ms
Container starts in bg…+4 800 ms
Fills 3 fields…
Clicks Create account
Backend responds< 300 ms

The warm-up request returns 401 Unauthorized (no token) — that's expected and ignored. The only goal is to force Cloud Run to spin up the container while the user is still filling the form.

Auth endpoints

Three endpoints cover the full auth lifecycle. All are proxied through nginx — the frontend container forwards /api/* to the Cloud Run backend.

JWT structure

The backend returns a signed JWT. It has three Base64url-encoded parts separated by dots.

eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJ1c2VySWQiOiJ1dWlkLTEyMyIsImVtYWlsIjoieW91QGV4YW1wbGUuY29tIiwiaWF0IjoxNzU1MDAwMDAwLCJleHAiOjE3NTU2MDQ4MDB9.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c
■ Header — alg + typ
■ Payload — claims
■ Signature — HMAC-SHA256

Payload claims

userId
User's UUID from the database
email
User's email address
iat
Issued-at Unix timestamp
exp
Expiry timestamp (7 days from issue)

localStorage schema

Zustand's persist middleware writes auth state under the key schemavis-auth. The format is the Zustand persist envelope.

Key: schemavis-auth Value: { "state": { "token": "eyJhbGc…", "user": { "id": "uuid-123", "email": "you@example.com", "displayName": "Shreyas" }, "isAuthenticated": true }, "version": 0 }

Request interceptor

Every API call through apiClient automatically attaches the token. No manual header management required.

apiClient.interceptors.request.use((config) => {
  const raw = localStorage.getItem('schemavis-auth')
  const token = JSON.parse(raw)?.state?.token
  if (token) config.headers.Authorization = `Bearer ${token}`
  return config
})
On page refresh, useAuthHydrated() waits for Zustand to rehydrate from localStorage before the router decides to redirect. This prevents a flash-to-login for already-authenticated users.
